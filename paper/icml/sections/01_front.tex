\begin{abstract}
Dense retrieval provides an effective similarity primitive, while structured search efficiently handles exact filters. Many useful constraints---such as \emph{minimalist}, \emph{office-appropriate}, or \emph{not sporty}---are latent semantic predicates: they are semantic judgments rather than stored catalog facts, and they are awkward to express as one query--item similarity. We study a \emph{compile once, execute cheaply} design in which expensive semantic supervision is moved offline, items share one low-bit representation, and each latent predicate is compiled into a reusable search-time program.

The original Random Semantic Algebra (\rsa) instantiation uses random orthogonal projections, low-bit quantization, and sparse boosted lookup tables. The strongest compact design in our study is instead a centered binary compiler: a 384-dimensional item is stored as 384 sign bits plus two per-item reconstruction scalars (56 bytes/item), while a supervised linear semantic head is quantized to four-bit weights and executed through four packed bit planes (about 216 bytes/predicate). We compare this design against sparse 1/2/4-bit \rsa programs, zero-shot MiniLM directions, a full-precision linear semantic proxy, and a PQ64 baseline that compiles the same linear proxy into product-quantization lookup tables.

On 44,072 fashion products, with MiniLM titles as the search-side representation and CLIP images as an independent teacher, Binary1-LS2-int4 reaches 0.337 recall at 20\% candidate retention, versus 0.207 for dense truncation, 0.352 for PQ64, and 0.363 for the FP32 semantic proxy. It therefore recovers 83\% of the incremental FP32 recall over dense retrieval while using 56 bytes/item and about 216 bytes/predicate. For PQ64 we distinguish persistent state from active execution state: a compact 1.55\,KB linear head plus shared codebook can be stored per concept, while the native executor used in our microbenchmark materializes a 65.5\,KB lookup table on activation.

We then execute the compiled predicates \emph{inside} HNSW traversal. On the strict first held-out split, using 1,000 queries for each of three predetermined three-predicate sets, $K=50$, and semantic selectivities from 50\% to 2\%, live Binary1 execution reaches Traversal Recall@50 between 0.955 and 0.992. A selectivity-aware HNSW over-fetch baseline swept up to $2\times K/s$ candidates, where $s$ is the eligible fraction, does not come within 0.005 recall of live traversal in any of the 15 predicate-set/selectivity conditions. At 5\% and 2\% selectivity, live traversal is also faster on average than this largest tested over-fetch point (9.82 vs. 10.27\,ms and 14.57 vs. 20.14\,ms) while retaining substantially higher traversal recall. The incremental compiled-predicate cost is approximately 96--134\,ns per predicate invocation, or 0.16--0.22 of the measured scalar 384-D dot-product cost on the same CPU. The strongest supported result is therefore a systems one: reusable soft predicates can be compiled into tiny programs over a shared low-bit substrate and executed directly during ANN search with a favorable quality--memory--latency trade-off.
\end{abstract}

\section{Introduction}
Modern search engines expose two mature computational languages. Dense retrieval expresses semantic similarity through inner products or cosine similarity. Structured retrieval expresses exact predicates---brand, size, category, availability---through inverted indexes, bitmaps, or relational filters. A large class of useful constraints is neither: \emph{minimalist}, \emph{office-appropriate}, \emph{technical}, \emph{quiet luxury}, and explicit negations such as \emph{not sporty} are semantic judgments rather than stored facts.

A dense query vector can absorb these words into one score, but logical composition becomes implicit. At the other extreme, a large VLM or LLM can evaluate each predicate directly, but per-candidate model inference inside a retrieval loop is expensive. Recent semantic-operator systems and semantic-filter cascades make this execution problem explicit \citep{patel2025lotus,kim2026semanticfilter,dong2026compilation}.

We study a third design point: \emph{compile once, execute cheaply}. Items are mapped once into a concept-independent low-bit code. Each semantic concept is learned offline as a small executable program over that code. Query understanding selects and composes already-compiled predicates. The same programs can be used as a candidate-side semantic stage, or---in the stronger systems configuration studied here---as soft eligibility predicates evaluated during dense HNSW traversal. Exact catalog filters and downstream ranking remain conventional components.

Our contributions are fourfold. First, we formulate semantic predicate compilation as a two-sided compression problem: both item bytes and predicate-program bytes matter when a catalog serves many reusable concepts. Second, we study two compiler families over a shared search-side embedding: sparse boosted LUT programs on 1/2/4-bit substrates, and a centered 1-bit two-level reconstruction whose int4 semantic heads execute through bitwise population counts. Third, we retain calibrated log-probability composition as a simple query algebra for independently trained positive and negated predicates. Fourth, we integrate the strongest tiny-program compiler into HNSW and evaluate traversal recall, live predicate cost, and latency against a selectivity-aware over-fetch baseline across three independently chosen predicate sets and five semantic selectivities.

The experiments revise an earlier interpretation of the project. Random 4-bit sparse LUTs remain a strong compressed semantic executor, but they are not the best Pareto point in the current benchmark. The centered binary int4 compiler is smaller on both the item and active-program axes and modestly more accurate, while PQ64 remains the strongest compressed quality and large-pool microkernel baseline. We therefore treat random rotation and the particular 4-bit code as design choices, not as the central claim.

We do \emph{not} claim that the binary code replaces ANN geometry, nor that the calibrated product rule is a new probabilistic operator. In fact, the HNSW experiments support the opposite separation: dense similarity should continue to navigate the graph, while compiled semantic programs decide soft result eligibility. The resulting systems object is a programmable semantic filter that can be deployed without materializing one catalog bitmap per learned concept.
