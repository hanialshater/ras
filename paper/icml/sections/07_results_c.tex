\subsection{Composition depth is confounded by prevalence}
A raw stratification by the number of latent predicates suggests larger semantic gains for deeper conjunctions. However, deeper conjunctions also have lower teacher prevalence inside the candidate pool, which makes fixed-budget pruning easier. We therefore re-analyzed the per-query 20\% recall deltas with pool prevalence as a covariate. In an exploratory OLS regression of method-minus-dense recall on latent count and teacher prevalence, the latent-count coefficient is $-0.0033$ for Binary1-LS2-int4 ($p=0.58$) and $-0.0026$ for RSA4 ($p=0.67$). We therefore find no evidence in this benchmark that composition depth itself increases the advantage after accounting for prevalence, and we do not use the raw depth trend as a headline result.

\subsection{Live semantic predicates inside HNSW}
The preceding microkernel asks how quickly a fixed candidate array can be scored. We next move the compiled predicate into ANN traversal itself. Dense similarity remains the HNSW navigation score; semantic programs only decide whether a visited node may enter the valid result beam. Semantically invalid nodes remain traversable, so the soft predicate does not disconnect the graph. A dense bound is checked before semantic execution, which avoids touching the predicate program for neighbors that cannot improve the current valid beam.

Table~\ref{tab:livehnsw} reports the fair full-data experiment. The indexed set is the strict held-out split of the 44,072-product source catalog. We run 100 deterministic query items with $K=50$, $ef=128$, and three active semantic predicates. The library filtered-HNSW baseline and our custom traversal use the same HNSW graph and the same normalized-dot distance. Predicate thresholds are selected to produce target eligibility fractions from 50\% to 2\%. The filtered baseline uses a materialized semantic predicate; the live method includes the actual Binary1-LS2-int4 program execution inside the timed traversal.

Two observations matter. First, post-filtering collapses as the learned predicate becomes selective, while both filter-aware traversals preserve roughly 0.97--0.98 Recall@50. Second, the live compiled-predicate traversal uses 43--52\% of the mean latency of the materialized filtered-HNSW baseline in this implementation, despite paying the semantic-program cost online. Across the sweep, live execution exactly matches the result IDs of the corresponding materialized custom traversal. The incremental program cost is stable at roughly 108--114\,ns per predicate evaluation; at 2\% selectivity the live traversal performs about 28.1k predicate evaluations and adds 3.11\,ms over the same custom traversal with free materialized semantics.

The result should not be read as a universal claim that a custom HNSW implementation is twice as fast as every filtered ANN system. It is evidence for the narrower point needed by this paper: the tiny compiled predicate is cheap enough to live inside graph traversal, and doing so avoids the severe recall loss of post-filtering at low semantic selectivity.
