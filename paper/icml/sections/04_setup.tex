
\section{Experimental Setup}
\paragraph{Dataset.} We use Fashion Product Images Small \citep{fashiondataset}. The exploratory mechanism benchmark samples 30k products. The main independent-teacher benchmark uses all 44,072 available products.

\paragraph{Mechanism benchmark.} Product titles are encoded by MiniLM \citep{reimers2019sbert,wang2020minilm} into 384-dimensional normalized vectors. Fourteen structured fields serve as concept labels. Product titles often contain those labels, so this benchmark is intentionally a representation/compiler mechanism test, not a leakage-free latent-semantic benchmark. Results use the original 65/35 train/test split; binary thresholds are fit on train.

\paragraph{Independent semantic teacher.} For the main benchmark, MiniLM title embeddings provide retrieval and all search-side semantic representations. CLIP ViT-B/32 image semantics \citep{radford2021clip} independently define eight latent concepts: minimalist, office-appropriate, technical/sporty, retro, elegant, relaxed, chunky, and quiet luxury. For each seed, the catalog is split strictly into 52\% fit, 13\% calibration, and 35\% test (22,916 / 5,730 / 15,426 products). Seeds 7, 17, and 27 define three independent splits. For each concept, CLIP scores each image against positive and negative prompt sets; a threshold chosen only on the fit split sets 40\% positive prevalence and is frozen for calibration and test. All learned search-side methods see only MiniLM features.

\paragraph{Predicate models.} We compare the following representations under the same split and calibration protocol. \textbf{RSA1/2/4} use 24 unary boosted LUTs and two pair LUTs per concept; RSA2 and RSA4 use random orthogonal projections with 2-bit and 4-bit quantile bins, while RSA1 is tested with both identity and random-centered sign codes. \textbf{Binary1-LS2} uses centered 1-bit documents plus two FP32 per-item reconstruction levels and compiles the same supervised linear semantic head with either FP32 or int4 predicate weights. \textbf{PQ64} uses 64 eight-bit PQ subcodes and compiles the FP32 linear head into 64$\times$256 lookup values. \textbf{FP32 linear} is a class-balanced logistic model on the original 384-dimensional MiniLM vectors and serves as a search-side semantic ceiling for linear information. We additionally report two training-free MiniLM baselines: a concept-name direction and a positive-minus-negative prompt direction. All supervised predicate scores are scalar-calibrated on the held-out calibration split before composition.

\paragraph{Storage accounting.} Reported item bytes assume packed representations. We distinguish persistent per-concept state from larger activation-time state when the executor materializes it. The principal configurations are: FP32 1,536 B/item and 1,548 B/concept; PQ64 64 B/item, a 1,548 B persistent linear head per concept plus one shared 393,216 B codebook, and a 65,548 B materialized LUT per \emph{active} concept in the native executor; Binary1-LS2-int4 56 B/item and 216 B/concept; RSA1 48 B/item and 292 B/concept; RSA2 96 B/item and 580 B/concept; and RSA4 192 B/item and 3,652 B/concept. Joint vocabulary-scale examples use persistent state and exclude graph/container overhead.

\paragraph{Compound-query generation.} Queries are generated using fit data only; test labels never influence query selection. Each query contains one to three positive latent predicates, optionally one negated latent predicate, and zero to two exact filters drawn from color, category, article type, gender, and master category. Exact-filter combinations must have sufficient fit support, and the complete semantic conjunction must have at least 100 positive fit examples. We sample 200 valid compound queries per split, yielding 600 query--split cases.

\paragraph{Search protocol.} For each query, MiniLM retrieves the top 5,000 held-out test products. Exact constraints are then applied as conventional filters. At each retained fraction $r\in\{1,.5,.4,.3,.2,.1,.05\}$, all methods keep exactly the same number of candidates. The dense baseline orders by query--item cosine similarity. Compiled predicate methods order by Eq.~\eqref{eq:composition}; the FP32 proxy uses the same algebra on calibrated full-precision concept logits. An oracle ordering places all teacher-relevant items first and therefore provides a budget-constrained upper bound. Recall and purity are measured against the CLIP-defined semantic conjunction \emph{within the exact-filtered top-5,000 ANN pool}; they are not global catalog recall.

\paragraph{Statistics.} We report means over the 600 query--split cases and 95\% query-level bootstrap intervals from 2,000 resamples. Paired intervals are computed on per-query differences. Because the three splits share one catalog and one latent vocabulary, these intervals should be read as descriptive uncertainty for this benchmark rather than as 600 fully independent real-world queries.

\paragraph{Native execution benchmark.} For the first strict split, the experiment exports the actual held-out FP32 vectors, PQ codes/LUTs, Binary1-LS2 bit codes/corrections/int4 bit planes, and RSA2 codes/programs. A single-threaded Rust release build physically tiles the 15,426 real held-out rows to a 500k-item resident working set and samples candidate sets of 5k, 20k, and 100k items. We evaluate 1, 2, 4, and 8 simultaneously active predicates and report the median of five timed repetitions. The runtime was an x86-64 Colab environment; the CPU model was not recorded, so throughput numbers are implementation evidence rather than hardware-normalized system comparisons. The FP32 path is a scalar reference implementation, not an optimized dense-linear-algebra baseline.

\paragraph{Reviewer-controlled live semantic-HNSW benchmark.} We separately index the first strict held-out split with normalized MiniLM vectors using $M=24$, construction $ef=200$, search $ef=128$, and $K=50$. We evaluate three predetermined sets of three active predicates: $+$minimalist $+$office-appropriate $-$technical/sporty; $+$elegant $+$quiet-luxury $-$chunky; and $+$retro $+$relaxed $-$office-appropriate. Each set is evaluated on 1,000 deterministic query items. Thresholds are chosen from the compiled semantic-score distribution to produce target eligibility fractions of 50\%, 20\%, 10\%, 5\%, and 2\%. Dense similarity alone controls graph navigation; the live method executes the Binary1-LS2-int4 programs to determine result eligibility while invalid nodes remain traversable. Traversal Recall@50 is measured against brute-force dense top-$K$ among items satisfying the \emph{same compiled predicate}; it is an ANN execution metric, not semantic relevance. The controlled materialized traversal uses the same custom graph search with precomputed semantic scores and isolates live program overhead. A separate ordinary-HNSW baseline retrieves approximately $mK/s$ candidates and post-filters them with the same materialized predicate, where $s$ is actual eligibility and the completed run uses $m\in\{0.75,1,1.5,2\}$. The public harness extends this sweep through $m=8$ to locate a genuine matched-recall operating point. Exact live/materialized result-ID parity is reported only as a correctness check.
